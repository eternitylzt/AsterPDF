# PDF 表单填写：实现前评估

日期：2026-09-28。以下保留实现前的评估过程。用户接受范围后，1.3.0 已实现首轮表单填写；当前使用说明、支持边界和实测结果见 [FORMS.md](FORMS.md)。提供的原样例未被修改。

## 样例检查

本地提供的候选人调查表共 16 页，包含 108 个标准 AcroForm 控件：44 个文本框、60 个单选按钮、4 个签名字段。单选按钮具有 30 个不同字段名；字段树有 108 个末端节点，与页面控件总数一致。没有 XFA；四个签名字段均未签名。两个文本字段使用日期规则 `AFDate_FormatEx("dd.mm.yyyy")`。本文不记录个人填写内容、字段值或原文件路径，也不随软件分发该文件。

这些信息证明样例采用的是现有引擎可识别的表单结构，不等同于已经实测填表、日期交互或保存兼容性。样例没有独立复选框、下拉列表，后续需要补充对应测试文档。

## 复杂度与体积

| 功能 | 复杂度 | 实现方式与边界 |
| --- | --- | --- |
| 单行 / 多行填空、复选框、单选按钮 | 中等 | 现有 PyMuPDF 读写字段，现有 Qt 控件负责交互；处理必填、只读、长度限制、Tab 顺序与单选组互斥 |
| 下拉列表、列表框 | 中等 | 显示值与实际存储值分开处理；测试可编辑列表与多选 |
| 日期选择 | 中等 | 识别常见日期格式，使用 Qt 日历，存回匹配格式的文本；不执行 PDF 中的任意脚本 |
| 撤销、恢复、保存后兼容显示 | 中等至较高 | 接入现有文档历史；同时验证字段值、父子字段关系和外观流，避免本软件看着正常而其它阅读器读到旧值 |
| 中文、缺失字体、富文本字段 | 较高 | 字体嵌入和外观重建需专门验证；不能静默把富文本样式或字形替换掉 |
| 任意 Acrobat JavaScript、动态 XFA、证书签名 | 高 | 不建议与常规填表一起承诺；签名验证、信任链和签署是独立功能 |

**常规 AcroForm 填写不需要新 PDF 引擎、浏览器或大型依赖，预计不会显著增加安装包体积。** 主要增加应用代码与少量图标、测试资源；确切大小要在实现并打包后测量。已有依赖可读取字段、按钮状态、选项、脚本描述并更新字段：[PyMuPDF Widget 官方文档](https://pymupdf.readthedocs.io/en/latest/widget.html)。Qt 已在应用中，日历、文本框和选择控件无需额外运行时。

## 建议的首轮支持范围

优先实现标准 AcroForm 的文字、复选、单选、列表、常见日期；点击原位填写，高亮可填写区域，支持 Tab 切换与保存。普通 PDF 上画出的表格线或扫描表格不属于可交互字段，自动识别它们需要另一个功能；现有文本批注可作为手工填写方式。

保存验证应同时检查 AcroForm 字段树的值、页面 Widget 的有效值与外观流，并在保存后重新打开，验证单选组、同名字段联动、中文、多行文本、日期及其它阅读器显示。保留交互性，不默认把表单压平。对未知脚本规则、签名字段和 XFA 明确提示支持边界，不尝试执行不受限的文档脚本。

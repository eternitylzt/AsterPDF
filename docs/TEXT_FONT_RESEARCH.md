# 文字编辑与字体处理研究 · 2026-11-06

本轮使用本机 Acrobat Pro DC 32-bit（21.1.20138.422477）及受控 PDF 样例，对照 AsterPDF 的原始正文编辑。结论只覆盖记录中的样例和静态接口，未反编译 Acrobat 的内部算法。

## REA 证据与边界

- `TouchUp.api` 的 PE 导入表包含字体枚举、字符定位及字体创建接口；完整表检查得到 332 个普通导入、14 个延迟导入。证据 `ev_e5cf4b903499f3906f1bf975f45dd2bce8ab1003c380d191bc1cc7da778c29d6`。
- `CoolType.dll` 导入 `GetFontData`，并声明对 `DWriteCreateFactory` 的延迟导入。其导出表只有三个入口，其中包括 `CTInit`。证据 `ev_bb41002d129287cc193181e52096b6ff4056ce485fdaed20856a9287299dd209` 和 `ev_0a547c66a42bb8524aec82a8f69d8c698848c8db4e0f07a07e30dcc3df85e1a9`。
- `AdobePDFL.dll` 的 1523 个导出中包含 `PDEFontEmbedNow`、`PDEFontSubsetNow`、`PDEFontCreateToUnicodeNow`、`PDEFontTranslateGlyphIdsToUnicode`，以及独立的 `PDETextGetTextMatrix` / `PDETextGetTextState` 和对应设置接口。证据 `ev_e67d8ef680e8b5061038f540db9afad1c6554768a89468abed70623adcbbfe9b`。

这些是已安装文件的静态声明，不能证明编辑时调用了哪个函数，也不能据此还原字体替换评分、段落重排或复杂文字塑形算法。完整 REA 导出保存在本次任务的 `outputs/text-font-research/rea-acrobat-text-font-evidence.json`。

## 实际行为与修复

| 观察到的问题 | 修复及验证 |
| --- | --- |
| 带 150% 水平缩放的字符替换后宽度改变；非均匀文字矩阵被误当作普通字号 | 从 PDF 文字状态保留实际字号、矩阵与缩放，新增字符使用对应变换。Acrobat 与 AsterPDF 同样执行 C→X 后，字宽均为 20.009765625 pt。 |
| 新增字符丢失字符间距/单词间距；再次编辑可能丢失间距语义 | 保留 Tc/Tw，并在新 CID 文字中正确表达单词间距；保存后重新打开及再次编辑都有回归用例。2 pt 字距样例中，新 X 字宽均为 13.33984375 pt。 |
| 同一文字块内部存在不同文字状态时，整体换字体错误复用首字符的状态 | 逐字保留各自的矩阵、字号和间距；完整 `ffi` 合字按原始字形整体处理，避免展开字符重叠。部分合字修改无法可靠映射时保留草稿并拒绝操作。 |
| 纯中文字体名经 ASCII 清洗后成为空串，不同字体被判为相同 | 名称规范化保留 Unicode 字母和数字，仅移除合法的 PDF 子集前缀。 |
| “中文＋数学斜体 𝛼”需要多个已安装字体，原实现整段只能用一个字体 | 对新增字符按实际字形覆盖选择字体，保留原字符的字体资源；样例保存后由 Acrobat 正确读回。 |
| 子集字体没有空格，却因跳过空白检查而写出空字符 | 普通空格和不换行空格必须有真实字形；CR/LF 作为控制字符单独处理。 |
| 常规文字粘贴可能复用粗体/斜体字体缓存 | 检查缓存字体的实际样式，避免错误复用。 |
| 全选正文后粘贴普通文本，Qt 的默认 MIME 路径丢失原字体属性 | 纯文本粘贴保留当前文字格式，安装版重复验证字体、字号和颜色；AsterPDF 自身的富文本粘贴仍保留其格式。 |

实际对照样例包含嵌入子集、粗斜体与 RGB 颜色、150% 水平缩放、2 pt 字距、中文和数学符号。AsterPDF 保存结果已在 Acrobat 关闭后重新打开读取，并由 Poppler 渲染检查；原字体资源、相邻文字和矩形图形保持。几何样例与 Acrobat 的基线位置最大差小于 0.001 pt。

## 验证与剩余边界

最终测试和安装版检查记录见 [VALIDATION.md](VALIDATION.md)。本轮检查使用 Windows 原生 Qt；无头 Qt 无法代表本机已安装字体集合。

- 这不是通用段落重排或复杂文字塑形实现。无法由同一字体覆盖的组合标记、变体选择符或连接符序列会保留草稿并拒绝拆分。
- 颜色输入仍采用 8-bit RGB：样例中新插入的 `x` 为 `(26, 64, 166) / 255`，原字形保留 PDF 中的浮点 RGB `(0.1, 0.25, 0.65)`。安装版再次编辑/保存后逐字颜色与先前结果完全一致，但不代表新增文字可无损保持任意浮点颜色或特殊色彩空间。
- 不支持的反向/旋转文字方向、参与文字裁剪或无法可靠映射的字形继续明确拒绝逐字编辑，不静默破坏页面。
- 已安装的 REA 当前未配置 Ghidra。本轮的问题可由静态接口证据、Acrobat 受控编辑和 AsterPDF 源码定位并验证，因此无需安装。若下一轮需要解释 Acrobat 内部字体替换规则或段落重排决策，再选择相关入口进行原生分析。
- 一项已有批注宽度自动应用 UI 测试超时；本轮未改动该批注行为，记录在验证日志，不能把此次结果解释为全仓库测试全通过。

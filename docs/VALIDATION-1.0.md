# AsterPDF 1.0 验证记录 / Validation

2026-09-17 · Windows 11 x64 · Python 3.12.10 · PySide6 6.10.2 · PyMuPDF 1.27.1 · pikepdf 10.3.0.

## 实际文档与性能

对用户提供的三页 `20241001.pdf` 使用临时工作副本测试，原文件 SHA-256 未改变。该文件不含独立栅格图片，其科研图主要由原生 PDF 绘图内容构成。

- 同机依次运行发布的 0.9 源码与 1.0：第一页对象识别 **22.625 → 4.482 秒**，约减少 80%。两版识别的 **375 个对象数据完全相同**，包括边界、内容范围、文字、字体、变换和字形细节。[对比](evidence/comparison-1.0.json)
- 另一轮实际流程：三页首次识别分别 **4.025 / 0.824 / 0.792 秒**；对象移动 **0.080 秒**；三页颜色统计 **0.077 秒**；两对颜色替换 **0.317 秒**。[记录](evidence/performance-1.0.json)
- 保存、重新打开：三页完整；第一页提取文字与修改前一致；没有把页面栅格化。私人测试文件及其截图不随软件发布。
- 独立生成的 **200 万像素**图片，两对替换 **0.057 秒**。像素结果确认按原色匹配，无连锁替换。专项测试覆盖图片内部区域与外部像素、保存重开、文本仍可搜索。

以上为本机单轮墙钟测量，后台负载可影响耗时；不承诺任意文件或设备达到同样速度。密集页面首次对象识别仍可能需要数秒。

## 工作流验证

- 换色：多页/区域、栅格像素、同步多对替换、背景白色替换、渐变样例颜色列表有界、保存/载入方案、区域边界开关、单步撤销及保存重开。
- 搜索：新文本框输入后直接搜索、草稿应用、两个匹配之间循环、当前匹配高亮、速览窗结果标记实际绘制；既有编辑/复制粘贴/字体保留回归。
- 关闭：多个修改文档，从首页发起关闭，自动激活待保存页；取消保留全部文档；保存与放弃逐个继续；模拟关闭事件重入也不跳过提示。旧版顺序保存与真实崩溃恢复测试保留。
- 设置：原像素动画画质与菜单勾选同步；换色参数、图片比例、页面操作和播放控制同步；Settings → 语言/Language 固定；语言切换保留文档。
- 显示：中英文、深色、小中大界面字号、标签角部高度；短文档自动速览尺寸和进度。检测到三块屏幕 DPR 为 2.5 / 1 / 1；本轮截图和字号检查不等同于重新完成全部多屏物理清晰度对比。[显示记录](evidence/display-1.0.json)
- GitHub 截图均由真实 Qt 界面生成，使用公开样例：[搜索与速览](evidence/overview-1.0.png)、[矢量区域提取](evidence/extract-1.0.png)、[自定义工具](evidence/tools-1.0.png)。原生 PDF 区域导出也实际执行。

## 已知限制与尚未验证

- Windows x64 实测；macOS/Linux 提供原生构建配置，本轮未构建或运行。没有测试 Acrobat、物理打印机；程序未签名、公证。
- 换色不支持矢量渐变着色、图案填充、批注和动画帧。模板/颜色键图片或不可解析内容会报错。已修改图片保留像素尺寸，以无损 RGB 存储，不保证原压缩流/色彩空间不变。
- 最多 64 个采样代表色是可见面积估计，不是全部 PDF 内部颜色的穷举。取色可选择列表之外的颜色；部分抗锯齿采样值需要容差。
- 区域换色采用矢量裁剪，部分提取器可能重复跨边界文字。任意字体、复杂文字排版和所有动画类型的兼容性并未因此扩大。
- 本轮没有重新进行长时间内存曲线或任意媒体帧率基准。播放诊断证明实际帧输出与基本交互，不保证所有编码/文件/平台。
- 未发布 GitHub 仓库或 Release；仓库地址仍由发布者配置。私人文件不进入源包。
